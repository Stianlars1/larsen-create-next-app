- We vendored the engine from rampkit at commit 48d6b33 and made two local

  implemented the OKLAB/OKLCH output that upstream lists but silently falls

## Session B - evaluate optional Tailwind support

Run this **after** Session A, since the preset question changes what a Tailwind
option would mean.

```
Read PROJECT.md in this repo first (/Users/stian/Larsen Utvikling/prosjekter/_TEMPLATES).
It is the maintained source of truth for @larsen-utvikling/create-next-app.

I am considering letting the CLI optionally scaffold with Tailwind CSS. I want
a recommendation and a plan, not an implementation. Push back if you think it
is a bad idea - I would rather hear that now.

CONTEXT YOU NEED TO WEIGH:

- "Never Tailwind" is currently a stated identity, not a default. It is written
  into the generated AGENTS.md and DESIGN.md, the package README, the landing
  page, both blog posts, and the CLI always passes --no-tailwind. Adding
  Tailwind means either softening that claim everywhere or scoping it carefully.
- The palette engine's shadcn preset already emits the hsl(var(--x)) idiom that
  shadcn/ui + Tailwind expects, so the colour half may be closer than it looks.
- Tailwind v4 moved to CSS-first config with @theme, which means its tokens are
  CSS custom properties too. Check whether that makes our design system layer
  compatible rather than redundant.
- rampkit has a tailwind preset that emits a module.exports config with 1-12
  keys. Check whether that is still the right shape for v4.

WHAT I WANT YOU TO ESTABLISH:

1. What would actually have to change. Be concrete and count it: a second set
   of template files, a second AGENTS.md and DESIGN.md variant, tailwind config
   or @theme generation from the palette, the prompt flow, the smoke test
   matrix, the landing page copy. Estimate the work honestly.

2. What breaks conceptually. The pitch is "the design system is five files you
   can read". Does a Tailwind variant still deliver that, or does it become a
   different product wearing the same name?

3. The alternatives, compared:
   (a) a --tailwind flag in this package,
   (b) a separate package that shares the palette engine,
   (c) no Tailwind, but a documented "how to add it on top" guide,
   (d) nothing.

4. A recommendation, with the reasoning stated plainly. Do not hedge.

Deliverables: findings, then a plan for whichever option you recommend. Record
the decision and its reasoning in PROJECT.md under section 8 either way - if we
decide against it, I want the reasoning written down so it is not relitigated
every few months.
```
